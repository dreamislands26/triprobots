# TRIPROBOTS Agents

Собственный сервис ИИ-агентов TRIPROBOTS: фронт-офис и маркетинг.

## Архитектура

Живые персональные данные не должны попадать на зарубежный сервер логики.

```text
Форма / Telegram
      ↓
Russia ingress + PostgreSQL
      ↓  только обезличенный текст
Agent logic / LLM
      ↓
Russia ingress
      ↓
клиент
```

`ingress/` принимает форму и Telegram webhook, первым сохраняет ПДн в PostgreSQL в РФ, маскирует контакты и только затем обращается к сервису логики.

Сервис `src/server.js` можно размещать на Render или другом сервере вне РФ, потому что его front-office endpoint закрыт `AGENT_INTERNAL_KEY` и принимает только обезличенный текст.

## Принципы

- агент предлагает — человек подтверждает всё, что уходит наружу от имени компании, кроме типовых ответов из базы знаний;
- персональные данные не передаются в сервис логики или модель;
- критичные действия выполняются отдельными инструментами с минимальными правами;
- публичные endpoints ограничиваются по частоте;
- `/api/marketing/draft` закрыт отдельным ключом;
- дневной бюджет модели ограничен `DAILY_LLM_TOKEN_LIMIT`;
- `/health` не раскрывает конфигурацию;
- если модель или зарубежная логика недоступны, ingress уже сохранил заявку и отвечает клиенту деградационным сообщением.

## Структура

- `ingress/` — входной сервер в РФ + Telegram webhook + хранение ПДн;
- `src/frontoffice/` — обезличенная логика фронт-офиса;
- `src/marketing/` — маркетинговый агент;
- `src/shared/` — LLM-адаптер и общая логика;
- `kb/` — база знаний;
- `prompts/` — системные промпты;
- `sql/` — схема PostgreSQL.

## Запуск логики агента

```bash
cd agents
cp .env.example .env
npm install
npm run dev
```

## Запуск ingress в РФ

```bash
cd agents/ingress
cp .env.example .env
npm install
npm run dev
```

Проверка обоих сервисов:

```bash
curl http://localhost:8788/health
curl http://localhost:8787/health
```

## Важное ограничение до production

Пока ingress и PostgreSQL физически не размещены в РФ и не проверены, **живую форму сайта к API не подключать**. Render использовать только с тестовыми/обезличенными данными.

Перед запуском живого трафика:

1. Поднять VPS + PostgreSQL в РФ.
2. Настроить резервную копию у второго провайдера в РФ.
3. Настроить одинаковый `AGENT_INTERNAL_KEY` на ingress и logic service.
4. Проверить доступность зарубежного logic service из российских сетей.
5. Создать Telegram-бота и направить webhook на Russia ingress.
6. Прогнать 30–50 тестовых сценариев фронт-офиса.
7. После этого заменить `mailto:` формы сайта на POST к ingress с таймаутом 6 секунд и fallback на контакты/mailto.

Архитектура не привязана к одному поставщику модели: используется OpenAI-compatible API через `LLM_BASE_URL` / `LLM_MODEL`.
